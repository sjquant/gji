# Switch tasks. Keep your place.

A review request shouldn't make you pack up a half-finished feature. `gji` is a
Git worktree CLI that gives each task a separate working directory, then helps
you move between them from your shell.

## What stays with each task

Your working files, dependency installation, and generated files live in that
task's directory. Open another worktree for a new feature, a PR review, or an
experiment; the files in the worktree you leave stay in place.

```bash
# While working on feature/payments:
gji new feature/search
gji pr 1234
gji go feature/payments
```

Replace `1234` with a real GitHub PR in your repository. With shell integration
enabled, the last command takes you back to `feature/payments`, including the
uncommitted changes you left there.

Use your existing Git commands, editor, and coding tools inside each worktree.
`gji` handles worktree creation, navigation, setup, and cleanup; it doesn't
replace your commit or review workflow.

## When it helps

- A PR needs review while your feature has uncommitted changes.
- You want to try an idea without changing the checkout you are using.
- Several branches need different dependencies or generated files.
- You keep human and AI-assisted tasks open in parallel and need separate files for each.

Git worktrees share the same repository history and refs. They aren't containers:
services, ports, external databases, and other machine resources still need your
project's own isolation or configuration. Each worktree also uses disk space for
its files and dependencies.
