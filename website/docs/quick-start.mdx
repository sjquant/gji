# Open a task. Come back to your work.

Start inside a repository on a named branch. You should have
[installed gji and loaded shell integration](./installation).

The goal is simple: open a separate working directory, then return to the files
you left open. You don't need to commit or stash them to try this.

## 1. Note where you are

```bash
git branch --show-current
git status --short
```

Remember the branch and any modified files. If your worktree is clean, that's
fine too.

## 2. Give a new task its own place

```bash
gji new feature/try-gji
```

Choose a different branch name if that one already exists. `gji` creates the
branch and worktree, runs supported dependency setup, and takes your shell to
the new directory. Setup may take time. Use `--no-install` to skip it for this
trial.

Check the new location:

```bash
pwd
git branch --show-current
```

You are now on `feature/try-gji` in its own directory. You can edit, run tests,
or open your editor here without changing files in the worktree you left.

## 3. Pick up where you left off

```bash
gji back
git status --short
```

You are back on the original branch. The modified files you noted in step 1
are still there. That is the core workflow: each task keeps its files while
you move between tasks.

Use `gji go feature/try-gji` to return to the trial worktree, or just `gji go`
to choose an open task.

## 4. Remove the trial directory when you're done

If you didn't leave any files you need in the trial worktree:

```bash
gji done feature/try-gji --keep-branch
```

This removes its working directory while retaining its branch. Review any
prompt before removing a worktree with changes. Uncommitted files aren't
recoverable through `gji undo`.

## Next: a real interruption

While working on a feature, use a PR number from your repository:

```bash
gji pr 1234
gji back
```

The PR opens in its own worktree; `back` returns to the one you just left.
For a particular destination, use `gji go <branch>`.

Continue with [daily workflow](./daily-workflow) for editors, experiments,
cross-repository navigation, and cleanup.
