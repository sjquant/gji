# 進行中の作業を保ち、終わった作業を削除する

`sync` でタスクを最新の状態にします。完了したワークツリーが 1 つなら `done`、複数の候補をまとめて確認するなら `clean` を使ってください。

## タスクを最新の状態にする {/* #bring-a-task-up-to-date */}

```bash
gji sync
```

リモートの変更を取得し、現在のブランチを設定された既定ブランチへリベースします。同期前にローカルの変更をコミットするなどして整理してください。リベースでは競合解決が必要な場合があります。続行や中止は、普段の Git の手順で行ってください。

現在のリポジトリのすべてのワークツリーを対象にする場合は、次のようにします。

```bash
gji sync --all
```

ブランチに属さないワークツリーは対象外です。必要に応じて、[設定](./configuration#use-a-different-sync-target)で `syncRemote` と `syncDefaultBranch` を指定してください。

## 1 つのワークツリーを完了する {/* #finish-one-worktree */}

まだ必要なファイルがワークツリーに残っていないか確認してください。

```bash
gji status
gji done feature/search
```

`done` はリンクされたワークツリーを削除し、そのブランチの削除も試みます。ブランチを残し、ディレクトリだけを削除するには次のようにします。

```bash
gji done feature/search --keep-branch
```

対話モードでは、未コミットの変更を破棄したり、未マージのブランチを削除したりする前に確認します。メッセージをよく読んでください。**ワークツリーと一緒に削除した未コミットのファイルや未追跡のファイルは、`gji undo` では復元できません。**

## 複数のワークツリーの削除を確認する {/* #review-several-worktrees-for-cleanup */}

```bash
gji clean
```

選択画面は現在のリポジトリから始まります。**Tab** を押すと、登録済みのすべてのリポジトリを対象にできます。各リポジトリの主ワークツリーと、現在のワークツリーは保護されます。調査できないリポジトリは空とみなさず、その旨を報告します。

何も削除せずに削除候補の計画を確認するには、次を実行します。

```bash
gji clean --stale --dry-run
```

`--stale` は、変更のないブランチ付きワークツリーのうち、上流ブランチがなくなり、変更が設定済みまたはリモートの既定ブランチにマージ済みのものだけを対象にします。スカッシュマージやリベースマージも含みます。

## パスで削除対象を絞る {/* #limit-cleanup-to-a-location */}

```bash
gji clean --path ~/worktrees/gji/spike
gji clean --path '../worktrees/*/experiment-*' --dry-run
```

通常のパスは、そのディレクトリと配下のディレクトリに一致します。`*`、`**`、`?` を含むグロブパターンはワークツリーのパス全体に一致します。シェルによる展開を防ぐため、引用符で囲んでください。文字としてのワイルドカードは、`'fix-\?-bug'` のようにバックスラッシュでエスケープします。複数のパターンのいずれかに一致させるには、`--path` を繰り返し指定します。

`--path` は登録済みのすべてのリポジトリを検索します。選択画面で **Tab** を押すと、現在のリポジトリに対象を戻せます。

## 対象を確認してから強制削除する {/* #force-removal-only-after-reviewing-the-targets */}

```bash
gji clean --stale --force
gji done feature/search --force
```

`--force` は確認を省略し、変更のあるワークツリーや未マージのブランチも削除できます。単に出力を減らすモードではありません。自動化に使う前に削除計画を確認し、必要なファイルを確かめてください。

## 記録された削除操作を取り消す {/* #restore-a-journaled-cleanup */}

```bash
gji undo --list
gji undo
# Or restore a specific operation:
gji undo <id>
```

取り消しは、操作ジャーナルに記録されたブランチとワークツリーの状態を復元します。既存の作業を上書きすることは拒否します。未コミットのファイル、未追跡のファイル、インストールした依存関係、フックが加えた変更は復元**しません**。

削除が複数のリポジトリにまたがる場合は、削除結果に表示されるリポジトリごとの取り消しコマンドを使ってください。関連コマンドは[コマンドリファレンス](./commands#maintenance)をご覧ください。
