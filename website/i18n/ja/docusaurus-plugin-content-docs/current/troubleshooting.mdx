# 作業に戻るために

まず、問題が起きているリポジトリ内で診断します。

```bash
gji doctor
```

Git、シェル、設定に関する案内を確認してください。以下では、よくある症状と対処方法を説明します。

## `gji go` が移動せずにパスを表示する {/* #gji-go-prints-a-path-instead-of-changing-directories */}

そのセッションでシェルラッパーを読み込んでいません。zsh では次のようにします。

```bash
eval "$(gji init zsh)"
```

bash では `zsh` を `bash` に置き換えてください。fish では `gji init fish | source` を実行します。もう一度 `gji go` を試してください。設定を保存するには `gji init` を実行し、シェルを再起動してから `gji doctor` で確認します。

シェルを指定したインストールやスクリプト専用の使い方については、[シェル連携](./shell-integration)をご覧ください。

## ワークツリーはあるのに依存関係がない {/* #the-worktree-exists-but-dependencies-are-missing */}

ワークツリーの作成が完了した後に、依存関係のセットアップが失敗する場合があります。エラーに表示されたパスから、作成済みのワークツリーに入ってください。インストールをやり直すためだけに削除して作り直す必要はありません。

その場所で、プロジェクトの通常のインストールコマンドを実行します。たとえば、次のようにします。

```bash
pnpm install
```

パッケージマネージャが使えることと、レジストリへアクセスできることを確認してください。インストールの失敗により `afterCreate` が実行されなかった場合は、必要に応じて設定済みのフックを再実行します。

```bash
gji run-hook afterCreate
```

再実行したいコマンドだけを実行してください。フックには副作用がある場合があります。フックのコマンド自体は、自動の依存関係インストールを再実行しません。

対応するロックファイルがない場合は、プロジェクト固有の[セットアップ用フック](./hooks)を設定するか、手動でインストールしてください。対応ツールは[依存関係の初期セットアップ](./configuration#dependency-bootstrap)をご覧ください。

## 依存関係のセットアップを省略したい {/* #i-want-to-skip-dependency-setup */}

1 つのタスクで省略するには、次のようにします。

```bash
gji new feature/search --no-install
gji pr 1234 --no-install
```

リポジトリで無効にする場合は、`.gji.json` の `dependencyBootstrap` を `off` に設定してください。

## ローカルのセットアップ用ファイルがコピーされない {/* #local-setup-files-werent-copied */}

設定されている一覧を確認してください。

```bash
gji sync-files list
```

コピー元のファイルは、現在のワークツリーだけでなく、**メインワークツリー**にある必要があります。コピー元にないファイルは無視し、コピー先の既存ファイルは上書きしません。一覧の変更は今後のワークツリーに適用します。継続的にコピーするわけではありません。[ローカルファイル](./configuration#sync-private-local-files)をご覧ください。

## `sync` が実行を拒否する、またはリベースが止まる {/* #sync-refuses-to-run-or-a-rebase-stops */}

```bash
gji status
git status --short
```

ローカルの変更があるか、`HEAD` がブランチから切り離されている可能性があります。同期の前にローカルの変更を整理するか、ブランチ付きのワークツリーに移動してください。すでにリベース中なら、普段の Git の手順（`git rebase --continue` または `git rebase --abort`）で解決してから再試行します。

## PR をローカルで開けない {/* #a-pr-wont-open-locally */}

番号や URL が現在のリポジトリに属していることと、現在の認証情報で Git リモートにアクセスできることを確認してください。`gji pr` は PR の参照を取得するもので、非公開リポジトリへのアクセス権を付与するものではありません。

ファイルを作らずに計画を確認するには、次を実行します。

```bash
gji pr 1234 --dry-run
```

## 登録されたリポジトリがすでに存在しない {/* #a-repository-in-the-registry-no-longer-exists */}

古い登録情報を確認してください。

```bash
gji doctor --fix
```

対話モードでは、存在しないリポジトリの登録情報を削除する前に確認します。確認済みの修正を非対話モードで適用するには、`gji doctor --fix --yes` を使ってください。Git、エディタ、シェルの設定を自動修復するものではありません。

## ワークツリーの削除が拒否される {/* #cleanup-refuses-to-remove-a-worktree */}

ローカルの変更、未マージのブランチ、現在または主ワークツリーでないかを確認してください。ディレクトリだけを削除する場合は、`gji done <branch> --keep-branch` でブランチを残します。

警告を消すためだけに `--force` を使わないでください。未コミットのファイルや未マージのブランチを削除する場合があります。先に[削除と復元](./sync-and-cleanup)を読んでください。`gji undo --list` は復元できる記録済みの操作を表示しますが、未コミットのファイルは復元できません。

## スクリプトでパスだけを取得したい {/* #i-only-need-paths-for-a-script */}

```bash
gji go --print feature/payments
gji root --print
```

これらのコマンドにはシェルラッパーは不要です。構造化された状態を取得する場合は、対応するコマンドの `--json` を使ってください。[コマンド](./commands#paths-and-json-for-scripts)をご覧ください。
