# 別のタスクを開いて、元の作業に戻る

リポジトリ内の、名前のあるブランチから始めてください。[gji のインストールとシェル連携の読み込み](./installation)が済んでいる必要があります。

ここで確かめるのは、別の作業ディレクトリを開いてから、開いたままにしていたファイルへ戻れることです。試すためにコミットやスタッシュをする必要はありません。

## 1. 現在の状態を確認する {/* #1-note-where-you-are */}

```bash
git branch --show-current
git status --short
```

ブランチと変更したファイルを覚えておいてください。ワークツリーに変更がなくても問題ありません。

## 2. 新しいタスクの作業場所を作る {/* #2-give-a-new-task-its-own-place */}

```bash
gji new feature/try-gji
```

同じブランチ名がすでにある場合は、別の名前を選んでください。`gji` はブランチとワークツリーを作成し、対応する依存関係のセットアップを実行して、シェルを新しいディレクトリへ移動します。セットアップに時間がかかる場合があります。今回は `--no-install` で省略してもかまいません。

新しい場所を確認します。

```bash
pwd
git branch --show-current
```

専用のディレクトリで `feature/try-gji` を開いた状態になりました。ここでは元のワークツリーのファイルを変えずに、編集、テストの実行、エディタの起動ができます。

## 3. 元の作業に戻る {/* #3-pick-up-where-you-left-off */}

```bash
gji back
git status --short
```

元のブランチに戻りました。手順 1 で確認した変更ファイルも残っています。タスクごとにファイルを保ったまま移動するのが、基本の使い方です。

試したワークツリーに戻るには `gji go feature/try-gji` を使います。開いているタスクから選ぶ場合は、`gji go` だけを実行してください。

## 4. 終わったら試用ディレクトリを削除する {/* #4-remove-the-trial-directory-when-youre-done */}

試用ワークツリーに必要なファイルを残していない場合は、次を実行します。

```bash
gji done feature/try-gji --keep-branch
```

ブランチは残したまま、作業ディレクトリだけを削除します。変更のあるワークツリーを削除するときは、確認メッセージをよく読んでください。未コミットのファイルは `gji undo` では復元できません。

## 次は実際の割り込みで試す {/* #next-a-real-interruption */}

機能開発の途中で、自分のリポジトリの PR 番号を使ってみてください。

```bash
gji pr 1234
gji back
```

PR は専用のワークツリーで開き、`back` で直前のワークツリーに戻れます。特定の場所へ移動するには `gji go <branch>` を使います。

エディタ、実験、リポジトリ間の移動、削除については、[日常のワークフロー](./daily-workflow)へ進んでください。
