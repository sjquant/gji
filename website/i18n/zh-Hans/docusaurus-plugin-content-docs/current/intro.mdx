# 切换任务，保留手头的修改

收到审查请求时，不必先收拾做到一半的功能。`gji` 是一个 Git 工作树命令行工具：为每项任务提供单独的工作目录，让你在终端中切换任务。

## 每项任务保留哪些内容 {/* #what-stays-with-each-task */}

工作文件、已安装的依赖和生成文件都放在对应任务的目录中。为新功能、PR 审查或实验打开另一个工作树时，原工作树里的文件会留在原处。

```bash
# While working on feature/payments:
gji new feature/search
gji pr 1234
gji go feature/payments
```

请将 `1234` 换成当前仓库中真实的 GitHub PR 编号。启用 Shell 集成后，最后一条命令会回到 `feature/payments`，之前留下的未提交修改也还在。

在每个工作树中，都可以继续使用原来的 Git 命令、编辑器和编程工具。`gji` 负责工作树的创建、导航、初始化和清理，不会替代你的提交或代码审查流程。

## 适用场景 {/* #when-it-helps */}

- 功能还没写完、修改尚未提交，就需要审查一个 PR。
- 想尝试一个想法，但不想改动正在使用的检出目录。
- 几个分支需要不同的依赖或生成文件。
- 同时进行人工开发和 AI 辅助任务，需要各自使用独立的文件。

Git 工作树共享同一仓库的历史和引用，并不是容器。服务、端口、外部数据库等系统资源，仍需由项目自行隔离或配置。每个工作树的文件和依赖也会占用额外的磁盘空间。
