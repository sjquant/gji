# 작업을 열어 두세요

중간에 다른 일을 하다가 돌아와야 하는 작업이라면 워크트리를 따로 만들어 두세요. 아래 명령은 [셸 통합](./shell-integration)이 불러와진 상태를 전제로 합니다.

## 기능 개발 시작 {/* #start-a-feature */}

```bash
gji new feature/search
```

브랜치와 워크트리를 만들고, 지원하는 의존성 설정을 실행한 뒤 셸을 해당 디렉터리로 이동시킵니다. 이전에 작업하던 파일은 원래 워크트리에 그대로 남습니다.

에디터도 함께 열려면 다음과 같이 실행합니다.

```bash
gji new feature/search --open --editor cursor
```

필요에 따라 `code`, `zed` 등 설치된 에디터 CLI를 선택하세요. `gji open --editor cursor --save`로 기본값을 저장하면 `--editor`를 생략할 수 있습니다.

기본적으로 새 브랜치는 메인 워크트리에서 시작합니다. 현재 워크트리의 커밋을 포함하려면 다음과 같이 실행하세요.

```bash
gji new feature/search-tests --from-current
```

현재 워크트리의 `HEAD`를 사용하며, 미커밋 파일은 가져오지 않습니다. 그 파일을 새 워크트리로 명시적으로 옮기려면 `--take`를 사용하세요. 원래 워크트리에도 남겨 두려면 `--copy`를 추가합니다.

```bash
gji new feature/search-fix --take
gji new feature/search-copy --take --copy
```

파일을 옮길지, 양쪽에 남길지에 따라 둘 중 하나를 실행하세요.

## 변경 사항을 정리하지 않고 PR 검토 {/* #review-a-pr-without-packing-up-your-changes */}

```bash
gji pr 1234
# Or: gji pr https://github.com/org/repo/pull/1234
```

저장소의 실제 PR 번호나 URL을 사용하세요. 검토용 워크트리가 따로 만들어지고 의존성도 설정됩니다. 돌아오려면 다음 명령을 실행합니다.

```bash
gji back
```

현재 워크트리의 PR 웹 페이지를 열려면 다음과 같이 실행하세요.

```bash
gji pr open
```

다른 연결 워크트리에 있는 PR을 고르려면 `gji pr open --select`를 사용하세요.

## 열어 둔 작업 찾기 {/* #find-the-work-you-left-open */}

```bash
gji                     # see the repository hub
gji go                  # choose a destination
gji go feature/payments  # go to a known branch
gji back                # return to the previous worktree
```

선택기는 현재 저장소에서 시작합니다. 등록된 모든 저장소를 포함하려면 **Tab**을 누르세요. **/**로 브랜치, 경로, PR, 작업 설명을 검색할 수 있습니다. 여러 저장소에 같은 브랜치 이름이 있으면 `repo/branch`를 사용하세요.

```bash
gji go api/main
```

더 이전에 방문한 곳으로 돌아가려면 `gji history`와 `gji back 2`를 사용하세요. 메인 저장소 체크아웃으로 돌아가려면 `gji root`를 사용합니다.

## 에디터를 열고 작업 설명 남기기 {/* #open-your-editor-and-label-the-task */}

```bash
gji open
gji task "Add payment retries"
```

작업 설명이 대화형 선택기에 표시되므로, 브랜치 이름만으로 작업 내용을 모두 설명할 필요는 없습니다. `gji task --clear`로 지울 수 있습니다.

`gji open`은 현재 워크트리를 대상으로 합니다. 다른 워크트리를 고르려면 `gji open --select`, 직접 지정하려면 `gji open feature/payments`를 사용하세요. VS Code, Cursor, Windsurf에서는 `--workspace`가 `.code-workspace` 파일을 생성한 뒤 엽니다.

## 실험할 공간을 따로 만들기 {/* #give-experiments-their-own-files */}

```bash
gji new --detached
```

브랜치 없이 워크트리를 만들면 이름부터 정하지 않고 바로 조사나 실험을 시작할 수 있습니다. 커밋을 이름 있는 브랜치에 남겨야 할 때는 그 전에 Git으로 브랜치를 만드세요. `--detached`와 `--from-current`는 함께 사용할 수 없습니다.

코딩 에이전트를 사용할 때는 작업마다 별도 워크트리를 만들고 해당 디렉터리에서 평소 도구를 실행하세요. 워크트리는 파일을 분리할 뿐, 공유 서비스나 데이터베이스, 수신 포트를 격리하지 않습니다.

## 새 디렉터리 없이 다음 작업 시작하기 {/* #reuse-a-worktree-when-you-dont-need-another-directory */}

```bash
gji new feature/next-task --branch-only
```

현재 워크트리에 **변경 사항이 없어야** 합니다. 설정된 원격 기본 브랜치를 갱신한 뒤, 다른 워크트리나 의존성 설정 없이 현재 위치에 새 브랜치를 만듭니다. 대신 로컬 기본 브랜치를 사용하려면 `--no-fetch`를 사용하세요.

순차적으로 작업할 때 사용하세요. 다른 곳에서 작업하는 동안 기존 작업을 열어 두어야 한다면 별도 워크트리를 사용하세요.

## 작업을 최신 상태로 맞추거나 마무리하기 {/* #update-or-finish-a-task */}

```bash
gji sync
```

현재 브랜치를 설정된 기본 브랜치 위로 리베이스하기 위해 원격 변경 사항을 가져옵니다. 작업이 끝나면 제거하기 전에 파일과 브랜치 상태를 검토하세요.

```bash
gji done feature/search
```

정리하면 워크트리와 브랜치가 모두 제거될 수 있습니다. `--keep-branch`, 미리 보기, 실행 취소의 한계는 [동기화와 정리](./sync-and-cleanup)를 참고하세요.
