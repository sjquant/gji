# 진행 중인 작업은 유지하고, 끝난 작업은 정리하세요.

`sync`로 작업을 최신 상태로 맞추세요. 완료된 워크트리 하나에는 `done`, 여러 후보를 함께 검토할 때는 `clean`을 사용합니다.

## 작업을 최신 상태로 맞추기 {/* #bring-a-task-up-to-date */}

```bash
gji sync
```

원격 변경 사항을 가져오고 현재 브랜치를 설정된 기본 브랜치 위로 리베이스합니다. 동기화 전에 로컬 변경 사항을 커밋하거나 다른 방법으로 정리하세요. 리베이스 중 충돌 해결이 필요할 수 있으며, 평소 Git 작업 방식으로 계속하거나 중단할 수 있습니다.

현재 저장소의 모든 워크트리에 적용하려면 다음과 같이 실행합니다.

```bash
gji sync --all
```

브랜치에 연결되지 않은 워크트리는 건너뜁니다. 필요하면 [설정](./configuration#use-a-different-sync-target)에서 `syncRemote`와 `syncDefaultBranch`를 지정하세요.

## 워크트리 하나 정리하기 {/* #finish-one-worktree */}

워크트리에 아직 필요한 파일이 없는지 확인하세요.

```bash
gji status
gji done feature/search
```

`done`은 연결된 워크트리를 제거하고 브랜치 제거도 시도합니다. 브랜치는 유지하고 디렉터리만 제거하려면 다음과 같이 실행합니다.

```bash
gji done feature/search --keep-branch
```

대화형 모드에서는 미커밋 변경 사항을 버리거나 병합되지 않은 브랜치를 제거하기 전에 확인합니다. 확인 메시지를 읽으세요. **워크트리와 함께 제거된 미커밋 파일과 추적되지 않은 파일은 `gji undo`로 복구할 수 없습니다.**

## 여러 워크트리를 함께 살펴보고 정리하기 {/* #review-several-worktrees-for-cleanup */}

```bash
gji clean
```

선택기는 현재 저장소에서 시작합니다. 등록된 모든 저장소를 포함하려면 **Tab**을 누르세요. 각 저장소의 주 워크트리와 현재 워크트리는 보호됩니다. 검사할 수 없는 저장소는 비어 있다고 간주하지 않고 별도로 보고합니다.

아직 삭제하지 않고 어떤 워크트리가 정리 대상인지 확인하려면 다음 명령을 실행하세요.

```bash
gji clean --stale --dry-run
```

`--stale`은 브랜치가 연결된 워크트리 중, 변경 사항이 없고 업스트림 브랜치가 사라졌으며 변경 내용이 설정된 기본 브랜치 또는 원격 기본 브랜치에 이미 병합된 것만 정리 대상으로 고릅니다. 스쿼시 병합이나 리베이스 병합도 포함합니다.

## 경로로 정리 대상 좁히기 {/* #limit-cleanup-to-a-location */}

```bash
gji clean --path ~/worktrees/gji/spike
gji clean --path '../worktrees/*/experiment-*' --dry-run
```

일반 경로는 해당 디렉터리와 하위 디렉터리에 일치합니다. `*`, `**`, `?`가 있는 글로브 패턴은 전체 워크트리 경로에 일치하며, 셸 확장을 막으려면 따옴표로 감싸세요. `'fix-\?-bug'`처럼 실제 와일드카드 문자 앞에는 백슬래시를 붙입니다. 여러 패턴 중 하나와 일치시키려면 `--path`를 반복하세요.

`--path`는 등록된 모든 저장소를 검색합니다. 선택기에서 **Tab**을 누르면 현재 저장소로 범위를 다시 좁힐 수 있습니다.

## 대상을 검토한 뒤에만 강제 제거 {/* #force-removal-only-after-reviewing-the-targets */}

```bash
gji clean --stale --force
gji done feature/search --force
```

`--force`는 확인을 생략하고, 변경 사항이 있는 워크트리를 제거하거나 병합되지 않은 브랜치를 삭제할 수 있습니다. 단순히 출력을 줄이는 모드가 아닙니다. 자동화에 사용하기 전에 정리 계획을 미리 보고 필요한 파일을 확인하세요.

## 기록된 정리 작업 되돌리기 {/* #restore-a-journaled-cleanup */}

```bash
gji undo --list
gji undo
# Or restore a specific operation:
gji undo <id>
```

실행 취소는 작업 기록(저널)에 남아 있는 브랜치와 워크트리 상태를 복원합니다. 기존 작업을 덮어써야 한다면 복원하지 않습니다. 미커밋 파일, 추적되지 않은 파일, 의존성 설치, 훅이 만든 변경 사항은 복원하지 **않습니다**.

여러 저장소를 정리했다면 정리 결과에 출력된 저장소별 실행 취소 명령을 사용하세요. 관련 명령은 [명령어 참고](./commands#maintenance)를 확인하세요.
