# gji 설치

CLI를 설치한 다음, 셸 통합을 한 번만 설정하세요. 그러면 `gji new`, `gji go`, `gji back`을 실행할 때 현재 셸도 해당 디렉터리로 이동합니다.

## 요구 사항 {/* #requirements */}

- npm 패키지를 실행할 **Node.js 20+**.
- **워크트리를 지원하는 Git**과 작업할 로컬 저장소.
- 자동 디렉터리 이동을 위한 **zsh, bash 또는 fish**.
- 브랜치나 풀 리퀘스트를 가져올 수 있는 Git 원격 저장소 접근 권한.

지원하는 잠금 파일을 찾으면 새 워크트리에 의존성을 설치합니다. 프로젝트에서 쓰는 패키지 관리자가 설치되어 있어야 합니다. 첫 설치에는 시간이 걸릴 수 있고 추가 디스크 공간도 필요합니다. `--no-install`로 생략할 수 있습니다.

## 설치와 셸 설정 {/* #install-and-set-up-your-shell */}

```bash
npm install -g @solaqua/gji
gji init
```

설정 마법사에서 셸 통합과 자동 완성을 설치하고, 사용할 수 있는 에디터를 선택할 수 있습니다. 계속하기 전에 **셸을 다시 시작**하거나 마법사가 안내한 설정 파일을 불러오세요.

저장소 안에서 결과를 확인합니다.

```bash
gji doctor
```

셸, Git, 설정에 대한 안내를 따르세요. 그런 다음 [첫 워크트리를 만드세요](./quick-start).

## 특정 셸 설정 {/* #set-up-a-specific-shell */}

dotfiles나 비대화형 환경을 설정할 때는 다음 명령을 사용합니다.

```bash
gji init zsh --write
# Or use your shell:
gji init bash --write
gji init fish --write
```

사용 중인 셸에 맞는 명령 하나만 실행하세요. 파일을 쓰지 않고 래퍼를 먼저 살펴보려면 다음 명령을 사용합니다.

```bash
gji init zsh
```

현재 세션에서만 셸 통합을 불러오거나 스크립트에서 사용하는 방법은 [셸 통합](./shell-integration)을 참고하세요. 셸 통합 없이도 워크트리 명령으로 디렉터리를 생성하거나 찾을 수 있지만, 부모 셸을 이동시킬 수는 없습니다.

## 선택 사항: 로컬 프로젝트 파일 준비 {/* #optional-prepare-local-project-files */}

새 워크트리에 **메인 워크트리**의 비공개 파일이 필요하다면 등록하세요.

```bash
gji sync-files add .env.local .npmrc
```

파일 목록은 전역 설정 파일의 해당 저장소 항목에 저장됩니다. 새 워크트리를 만들 때 의존성을 설치하기 전에 파일을 복사하며, 대상에 이미 있는 파일은 덮어쓰지 않습니다. [로컬 파일](./configuration#sync-private-local-files)을 참고하세요.

코드 생성처럼 추가 프로젝트 설정이 필요할 때는 [훅](./hooks)을 사용하세요. 기본 어댑터가 의존성을 설치하고 있다면 설치 훅을 따로 추가하지 마세요.

## 업데이트 {/* #update */}

```bash
npm install -g @solaqua/gji
```

셸을 다시 시작해 셸 통합을 다시 불러온 뒤 `gji doctor`를 실행하세요. 이동 명령이 디렉터리를 바꾸지 않고 경로만 출력한다면 [이동 문제 해결 절차](./troubleshooting#gji-go-prints-a-path-instead-of-changing-directories)를 따르세요.
