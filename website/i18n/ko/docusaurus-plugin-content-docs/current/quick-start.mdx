# 새 작업을 열고, 하던 일로 돌아오세요.

저장소에서 브랜치를 체크아웃한 상태로 시작하세요. [gji를 설치하고 셸 통합을 불러온 상태](./installation)여야 합니다.

여기서는 별도의 작업 디렉터리를 열었다가, 하던 작업의 파일로 돌아오는 흐름을 확인합니다. 미리 커밋하거나 스태시하지 않아도 됩니다.

## 1. 현재 위치 확인 {/* #1-note-where-you-are */}

```bash
git branch --show-current
git status --short
```

브랜치와 수정된 파일을 기억해 두세요. 워크트리에 변경 사항이 없어도 괜찮습니다.

## 2. 새 작업을 위한 공간 만들기 {/* #2-give-a-new-task-its-own-place */}

```bash
gji new feature/try-gji
```

같은 이름의 브랜치가 이미 있으면 다른 이름을 선택하세요. `gji`가 브랜치와 워크트리를 만들고, 지원되는 방식으로 의존성을 준비한 뒤 셸을 새 디렉터리로 이동시킵니다. 준비 과정에 시간이 걸릴 수 있습니다. 이번 시험에서는 `--no-install`로 생략할 수 있습니다.

새 위치를 확인합니다.

```bash
pwd
git branch --show-current
```

이제 새 디렉터리에서 `feature/try-gji` 브랜치를 사용하고 있습니다. 떠나온 워크트리의 파일을 바꾸지 않고 여기서 편집하거나 테스트를 실행하거나 에디터를 열 수 있습니다.

## 3. 하던 작업으로 돌아오기 {/* #3-pick-up-where-you-left-off */}

```bash
gji back
git status --short
```

원래 브랜치로 돌아왔습니다. 1단계에서 확인한 수정 파일도 그대로 있습니다. 작업별로 파일을 그대로 두고 필요한 작업으로 이동하는 것이 기본 사용법입니다.

시험용 워크트리로 돌아가려면 `gji go feature/try-gji`를 사용하고, 열려 있는 작업을 선택하려면 `gji go`만 실행하세요.

## 4. 끝나면 시험용 디렉터리 제거 {/* #4-remove-the-trial-directory-when-youre-done */}

시험용 워크트리에 더 이상 필요한 파일이 없다면 다음 명령으로 정리하세요.

```bash
gji done feature/try-gji --keep-branch
```

브랜치는 유지하고 작업 디렉터리만 제거합니다. 변경 사항이 있는 워크트리를 제거하기 전에는 확인 메시지를 검토하세요. 미커밋 파일은 `gji undo`로 복구할 수 없습니다.

## 다음: 실제 작업 중에 전환하기 {/* #next-a-real-interruption */}

기능을 개발하는 중에 저장소의 PR 번호를 사용해 보세요.

```bash
gji pr 1234
gji back
```

PR은 별도 워크트리에 열리고, `back`은 방금 떠나온 워크트리로 돌아갑니다. 특정 목적지로 이동하려면 `gji go <branch>`를 사용하세요.

에디터, 실험, 저장소 간 이동, 정리는 [일상 작업 흐름](./daily-workflow)에서 이어서 살펴보세요.
