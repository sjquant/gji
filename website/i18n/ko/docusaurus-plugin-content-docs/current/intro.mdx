# 작업을 전환해도, 하던 일은 그대로.

리뷰 요청이 와도 하던 기능 개발을 정리할 필요는 없습니다. `gji`는 작업마다 디렉터리를 따로 만들고, 셸에서 작업 사이를 쉽게 오갈 수 있게 해 주는 Git 워크트리 CLI입니다.

## 작업을 전환해도 유지되는 것 {/* #what-stays-with-each-task */}

작업 파일과 설치한 의존성, 생성 파일은 각 작업의 디렉터리에 남습니다. 새 기능을 개발하거나 PR을 검토하거나 실험하려고 다른 워크트리를 열어도, 원래 워크트리의 파일은 바뀌지 않습니다.

```bash
# While working on feature/payments:
gji new feature/search
gji pr 1234
gji go feature/payments
```

`1234`를 저장소의 실제 GitHub PR 번호로 바꾸세요. 셸 통합이 활성화되어 있으면 마지막 명령이 `feature/payments`로 이동시켜 주며, 그곳에 남겨 둔, 아직 커밋하지 않은 변경 사항도 그대로 있습니다.

각 워크트리에서 기존 Git 명령, 에디터, 코딩 도구를 사용하세요. `gji`는 워크트리 생성, 이동, 설정, 정리를 담당하며, 커밋이나 리뷰 방식을 대신하지 않습니다.

## 이런 때 유용합니다 {/* #when-it-helps */}

- 기능 작업에 미커밋 변경 사항이 있는데 PR을 검토해야 할 때.
- 사용 중인 체크아웃을 바꾸지 않고 아이디어를 시험하고 싶을 때.
- 여러 브랜치에 서로 다른 의존성이나 생성 파일이 필요할 때.
- 사람이 직접 하는 작업과 AI를 활용한 작업을 동시에 진행하면서 파일을 따로 써야 할 때.

Git 워크트리는 같은 저장소의 이력과 참조를 공유합니다. 컨테이너는 아닙니다. 서비스, 포트, 외부 데이터베이스, 그 밖의 시스템 자원은 프로젝트에서 직접 격리하거나 설정해야 합니다. 워크트리마다 파일과 의존성을 저장할 디스크 공간도 필요합니다.
